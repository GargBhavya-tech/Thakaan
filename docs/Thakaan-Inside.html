Thakaan · how the app thinks

Inside Thakaan

Which sensors we read, which models we run, which ones we trained, and the maths that turns all of it into one of four words: Cool, Warming, Strained, Danger. Written from the actual code in app/src/main/java/com/thakaan.

11 sensorsAll inside the phone. No smartwatch, no internet in the main loop.
5 + 4 models5 downloaded ready-made, 4 we trained ourselves on made-up (simulated) data.
0 models decideThe level comes from physics formulas and fixed rules. AI models only give a second opinion or reword a sentence.

4 · How it all combines

Two layers: a score, and floors under it

The risk engine (risk/RiskEngine.kt) runs every time new data arrives. It does three things.

  1. Squash four sub-scores into one number. Exposure E, Body B, Brain N and Symptoms S, each between 0 and 1, are added with weights and passed through a sigmoid to give the Strain Score (TSS) from 0 to 100.
  2. Check the anchor rules. These are hard "if this, then at least that level" rules taken from occupational-health practice, for example "core trend at 38.5 °C → at least Strained" or "2 brain families slower → at least Strained". Each anchor is a floor.
  3. Take the highest. Shown level = max(level from score, every anchor). Then smooth it: rise immediately, but drop only one step at a time after the score has been clearly lower for a few minutes.
● CoolTSS 0–29
▲ WarmingTSS 30–54
◆ StrainedTSS 55–79
■ DangerTSS 80–100

The one rule behind every combination: use max(), never average

Whenever two sources disagree, Thakaan keeps the more worried one. Missing data counts as bad, not as fine. Some places you will see this:

  • Two core-trend filters (plain and adaptive): anchors use max(plain, adaptive).
  • Rule forecast vs GRU forecast: max(rule, model), so a model can only bring a warning earlier.
  • Weather file missing → WBGT counts as the hottest case. Shade unknown → counts as sun.
  • Heart reading goes old → the last body strain is held, it does not fade back to "fine".
  • Gemma's sentence can never change the level or the action; those come from the engine only.
5 · Maths

The Strain Score (TSS)

In plain words: work out four "how bad is it" numbers between 0 and 1, add them up with equal weights, subtract 3, and squash through a sigmoid (an S-curve that turns any number into something between 0 and 1). Multiply by 100.

z = 3·E + 3·B + 3·N + 3·S − 3 TSS = 100 · 1 / (1 + e^(−z)) // sigmoid, gives 0..100

The −3 means: with everything at 0, TSS = 100/(1+e³) ≈ 4. Any one sub-score at full (1.0) gives z = 0, so TSS = 50. Two at full gives z = 3, TSS ≈ 95.

E · Exposure (how hard the environment is pushing)

E = clamp( (0.5·W + 0.2·sun + 0.15·rest + 0.15·now) × time × acclim , 0, 1 ) W = WBGT score: 0 below 24 °C, 0.35 at 28, 0.7 at 31, 1.0 at 33 (straight lines in between) sun = min(sun-minutes / 120, 1) rest = min(rest-debt-minutes / 60, 1) now = 1 if in sun right now (or unknown), 0 if in shade time = 1.0 at 12:00–16:00, 0.85 at 10–12 & 16–17:30, 0.65 at 8–10 & 17:30–19, else 0.45 acclim= 1 − 0.2 · min(days used to heat / 10, 1) // up to 20% less for acclimatised workers

B · Body (what the heart and body estimates say)

B = max of: PSI / 10 core trend: 0 at 37.0 °C → 1 at 38.5 °C (38.0 °C if not acclimatised) resting HR held ≥ 5 min: 0.3 at 90 bpm → 0.9 at 110 bpm water deficit: 0.5 · min(deficit% / 4, 1) PSI = 5·(core − 37)/2.5 + 5·(HR − 60)/120 // Physiological Strain Index, 0..10

B uses max, not a sum: one clearly bad body sign is enough. If the last heart reading is older than 15 minutes, B is held at the last fresh value; in very hot exposure (E ≥ 0.8) it cannot go below 0.5 × E.

N · Brain and S · Symptoms

N = 0, 0.4, 0.8, 1.0 for 0, 1, 2, 3+ brain families flagged S = 1 if confusion or faintness, else min(0.4 × number of symptoms, 1)

Anchors (floors)

5 · Maths

Core-temperature trend from heart rate (ECTemp)

The idea: when your core heats up, your heart beats faster. If we know the curve "expected heart rate for each core temperature", we can work backwards from heart rate to a core guess. But heart readings are noisy and arrive only at stops, so we use a Kalman filter: it keeps a best guess ct and a "how unsure am I" number v, and every minute does two steps.

  1. Predict: without new data the guess stays put, but we become a bit less sure (v grows).
  2. Correct: when a heart rate arrives, compare it with the heart rate we expected. Move the guess toward the reading, by an amount that depends on how unsure we were versus how noisy heart rate is.
// one minute v⁻ = v + Q // predict: Q = 0.000484 (≈ 0.022 °C per minute drift) M = h'(ct) // slope of the HR curve at the current guess K = v⁻·M / (M²·v⁻ + R) // Kalman gain: how much to trust the new reading. R = 356.45 (≈ 18.9 bpm noise) ct = ct + K·(HR − h(ct)) // correct the guess v = (1 − K·M)·v⁻ // now more sure h(ct) = −4.5714·ct² + 384.4286·ct − 7887.1 // published curve: expected HR at core temp ct
ct
current best guess of core temperature (start 37.1 °C, or a time-of-day value: 36.8 at 05:00 rising to 37.4 at 17:00)
v
how unsure the guess is (variance). Starts at 0.02, or 0.2 if the worker logs on already hot
HR
that minute's heart rate: median of readings between 40 and 210 bpm
K
between 0 and about 0.03 °C per bpm. Big when we are unsure, small when we are confident

Extra pieces we added on top

  • Gaps: no reading for 12 minutes? We run 12 "predict only" steps, so v grows by 12·Q. Uncertainty can only grow across a gap, never shrink.
  • Outlier gate (NIS): if (HR − h)² / (M²·v⁻ + R) > 3.84 (the 95% line of a chi-square test), the reading is too surprising and is skipped like a missing minute.
  • Personal curve: after onboarding, h(ct) becomes an S-shaped curve with your own floor A (lowest 5-minute resting HR) and ceiling K = 208 − 0.7·age (max heart rate): HR = A + (K−A) / (1 + 0.06·e^(−0.89(ct−37.84)))^(1/0.07).
  • Adaptive R: if the last 4 surprises average more than 6 bpm the same way, the extra heart rate is probably humidity or dehydration, not heat. R is inflated (up to 10×) so the core guess does not run away. Because that could lower the guess, anchors use max(plain, adaptive).
  • Check: the plain filter must match 7 published reference cases in ectemp_vectors.json to 1e-9. It does, on the laptop and on the phone.

This number is never shown to the worker as a temperature. It only drives the score and anchors. ECTemp is patent-covered (US 10,702,165).

5 · Maths

Heat balance and water loss

Gagge two-node model: treat the body as two boxes, core and skin. Each minute (in 15-second sub-steps) heat flows in from your muscles and out through skin, sweat and breathing. Whatever is left over warms the box.

change in core = (M − breathing loss − K·(Tcore − Tskin)) / core heat capacity change in skin = (K·(Tcore − Tskin) − dry loss − sweat evaporation) / skin heat capacity M = metabolic heat = METs × body mass (from the activity) K = 5.28 + 1.163 × skin blood flow // more blood flow → more heat to the skin sweat = 170 × (body warmth above normal) × e^(skin warmth / 10.7) g/m²/h dry = (Tskin − T_operative) / (clothing + air resistance) // T_operative mixes air temp and radiant (sun) temp

Its job is a prior: between heart readings it nudges the ECTemp guess each minute. The nudge is clamped to at most +0.05 °C per minute warming and only −0.002 °C per minute cooling, and is exactly 0 if the weather is missing. So the model can warn earlier but cannot invent recovery.

Water lost (hydration ledger)

loss per minute = sweat × body surface area / 60 + (30 + 0.1·(M − 100)) / 60 // grams = ml body surface area = 0.202 × mass^0.425 × height^0.725 // DuBois formula deficit band (% of body mass): low = 0.8·loss − drinks − 100 ml per hour (unlogged sips) mid = loss − 0.9·drinks // this one feeds the score high = 1.2·loss − 0.8·drinks

A forgotten drink makes the number too high, which is the safe direction. After 45 minutes with a deficit over 1%, the app asks "did you drink?" before escalating.

5 · Maths

Pulse from a fingertip on the camera (PPG)

The idea: with the torch on and a finger on the lens, each heartbeat pushes more blood into the fingertip, which absorbs more light, so the picture gets slightly darker. Average the red value of each frame and you get a wave that beats with your heart. The hard part is cleaning it.

  1. Even spacing: camera frames arrive unevenly, so fit a smooth curve (natural cubic spline) through them and resample at exactly 100 per second. Flip the sign so a beat is a peak.
  2. Band-pass 0.5–4 Hz (30 to 240 bpm) with a Butterworth filter run forward then backward, so the peaks do not shift in time.
  3. Wavelet denoise: split the signal into coarse and fine parts (Daubechies-4), estimate the noise level as median(|finest part|)/0.6745, and shrink fine parts below σ·√(2 ln N) toward zero.
  4. Find beats: a peak is where the slope turns from up to down, with a "refractory" gap (at least 300 ms, or 55% of a beat) so the small second bump of each beat is not counted twice.
  5. Track heart rate over time (Viterbi): in each 8-second window, take the few strongest frequencies. Then choose one per window so the path is both strong and smooth: cost = −log(strength) + (jump in bpm)² / (2σ²). Viterbi is dynamic programming that finds the cheapest path through all windows.

Quality gates: a bad capture gives no number, only a retry prompt

5 · Maths

Sun, shade and the WBGT heat index

Sun or shade right now

We compare the light sensor with what the sun should give at this time and place. The sun's position comes from the NOAA formula. Clear-sky sunlight (Haurwitz) and cloud correction (Kasten–Czeplak):

clear sky (W/m²) = 1098 · sin(elev) · e^(−0.059 / sin(elev)) cloud factor = 1 − 0.75 · (cloud fraction)^3.4 // unknown cloud → 1 (assume clear: worst case) expected lux ≈ 110 lux per W/m² ratio = measured lux / expected lux ratio ≥ 0.45 → SUN ratio < 0.12 → SHADE colour temp ≤ 6300 K → sun-like ≥ 7000 K → shade-like (blue sky light)

Traps the code handles: the sensor tops out near 66,000 lux, so a pinned reading switches to the model value; a low sun behind the rider's body makes the sensor read "shade" falsely, so a dim reading is only believed if GPS sky view agrees. Unknown always counts as SUN.

GPS sky view

The sky is split into 10° cells. Each cell keeps a "log-odds" score of being open (positive = probably open), nudged every second by satellite signal strength and decayed by 0.85 each second so it remembers about 5–10 seconds. If cells near the sun's direction are blocked, you are probably under a tree or building. The rider's own body blocks satellites behind them, so the code learns that pattern and ignores it.

WBGT (Wet Bulb Globe Temperature)

WBGT is the standard number used worldwide for work-rest limits in heat. It combines air temperature, humidity, wind and sunlight. We use the Liljegren model: a published C program, compiled for the phone with the NDK and called from Kotlin through JNI.

inputs: air temp, humidity, pressure ← weather file sunlight = max(forecast, light sensor) in sun, 0.2 × forecast in shade wind = √(wind² + riding speed²), at least 0.5 m/s output: WBGT °C (null if anything is missing → treated as hottest)

Sun dose and rest debt

Sun dose counts minutes in direct sun, weighted by how high the sun is (noon counts more than morning). Rest debt grows when there has been no real rest: a real rest means shade and still for more than 5 minutes. A long red light in the sun does not count.

5 · Maths

Brain tests: noticing you are slowing down

The idea: heat makes the brain slower and clumsier before you feel ill. We run short tests and compare each score only with your own cool-morning scores on the same phone, same placement, similar time of day.

FamilyTestsWhat is measured
MotionTremor, walkingHand shake: power of acceleration between 4 and 12 Hz while holding the phone out. Walking: how uneven step timing is (coefficient of variation), side-to-side sway
TouchTapping, reaction timeTapping (Fitts): throughput = ID / time, with ID = log₂(distance / Wₑ + 1), Wₑ = 4.133 × spread of taps. Reaction (PVT-B, 3 min): mean of 1/reaction time; over 500 ms is a lapse
VoiceSpeech codeSay a 4-digit code: wrong digits, digits per second, long pauses
FaceEyes, yawnsPERCLOS = share of time eyes are ≥ 80% closed; yawns per minute
NavigationRidingHow erratic the riding pattern is (entropy)

Step 1 · Robust z-score: how unusual is this score for you?

z = (today's score − median of your baseline) / (1.4826 × MAD) MAD = median of |each baseline score − baseline median| // needs at least 5 baseline samples

Median and MAD are used instead of mean and standard deviation because one weird baseline test barely moves them. The 1.4826 makes MAD comparable to a standard deviation. The sign is set so that positive always means worse.

Step 2 · CUSUM: is it drifting, not just one bad try?

S = max(0, S + w × (min(z, 3.5) − 0.5)) alarm when S ≥ 4.5, clears when S ≤ 2.25

CUSUM ("cumulative sum") adds up how far each result is above normal. The −0.5 lets ordinary small bad days drain away. Capping z at 3.5 means one wild result cannot trigger it alone. The weight w is 1 normally, 0.5 if you slept badly and it is cool, 1.25 in heavy heat, and 0.7 if the baseline is from a different time of day.

Output: the set of families with an alarm. 1 family adds to N; 2 or more is an anchor (at least Strained).

5 · Maths

Chhaya Route: the shade-aware map

The idea: normal maps find the fastest route. Chhaya Route makes sunny roads "cost" more, and the extra cost grows with your strain. When you are Cool it is exactly the fastest route.

edge cost = travel time × (1 + λ(TSS) × sun fraction) + heat-island penalty + flood penalty λ(TSS) = 0 if TSS < 30 = 3 × min((TSS − 30) / 45, 1) otherwise // reaches 3 at TSS 75 heat-island penalty = 0.15 on sunny main roads flood penalty = 100,000 s on a road someone reported flooded (used only if no other way)
  • Search: our own Dijkstra shortest-path over a road graph built from OpenStreetMap. Runs offline in milliseconds.
  • Detour budget: Warming may add up to 1 minute, Strained up to 3 minutes (and inserts a water stop). The code tries the largest λ whose route still fits the budget. Danger drops the destination and goes to the nearest cool place to sit.
  • Where shade comes from: a Python script ray-casts sun rays against OSM building shapes for each road segment and half-hour. About 95% of building heights are guesses (3 floors × 3.2 m), so those segments are marked low-confidence and pushed halfway toward full sun.
  • Learning from riders (Bayesian update): per road and half-hour, shade = (s × computed + sunny passes) / (s + all passes), where the computed value counts as s = 4 observations (2 if low-confidence).
  • GPS snapping (HMM + Viterbi): each GPS point has a few candidate roads; the path that stays on the same or a connected road wins, so a jumpy GPS fix is not put on the parallel street.
5 · Maths

Forecast, air dose and the audit log

"Strained in about 15 minutes"

fit a straight line through the last 20 minutes of TSS // least squares slope = max(0, slope) // never promise recovery slope × (0.8 + 0.6 × planned route's sun share) // a sunny route steepens it minutes to Strained = (55 − TSS now) / slope, rounded to 5, shown only if ≤ 60 band = 1.64 × spread of the fit × √(1 + h/20) + 0.1 × h

Air dose (PM2.5 breathed in today)

dose += PM2.5 (µg/m³, from the saved forecast) × air breathed (L/min) × 1 min ÷ 1000 air breathed from heart rate (Greenwald 2019): VE = e^(−9.59) × HR^2.39 × age^0.274 × sex^(−0.204) × FVC^0.52 between heart readings: VE = 7 + 4 × (METs − 1)

Tamper-evident shift log

Each shift entry stores the SHA-256 hash of the previous entry and is signed with an ECDSA P-256 key kept in the phone's secure hardware (Android Keystore). Change, delete or reorder any entry and every later hash breaks. The supervisor console checks this in the browser. It proves nobody edited the log afterwards; it does not prove the readings were true.

    7 · Safety rules

    The eight guard switches

    Each fail-safe rule is a switch in Guards inside the risk engine. All are ON in the product. The Safety checks tab turns them off one at a time to prove each check really can go red, because a check that can never fail proves nothing. A property test (#41) runs thousands of random shifts and checks that losing information never lowers the level.

    SwitchWhat it guarantees
    holdWhenEvidenceStaleAn old heart reading is held, never faded to "fine"
    exposureFloorOnStaleNo fresh heart reading in severe heat: body strain is at least half of exposure
    unknownShadeIsSunGPS lost or light sensor blocked counts as sun
    missingWbgtIsHotNo weather counts as the hottest case, and is itself a Warming anchor
    brainFamiliesFloorStrainedTwo slower brain families force at least Strained
    llmCannotChangeLevelGemma's output is never read back as a level
    coreAnchorsFireCore-trend anchors fire at 38.5 °C (38.0 °C before acclimatisation); nothing waits for 39 °C
    independentHrRuleResting HR above 90–100 bpm raises the level even if the core estimate is wrong

    9 · Word list

    Terms used on this page

    Core temperatureTemperature deep inside the body. Normal ≈ 37 °C. Above ≈ 38.5 °C during work is the action point.
    WBGTWet Bulb Globe Temperature: one heat number that includes humidity, wind and sun, used for work-rest rules.
    AcclimatisedBody used to heat after ~7+ days of working in it. Sweats earlier, copes better.
    PPGPhotoplethysmography: reading the pulse from changes in light passing through skin.
    rPPGRemote PPG: the same thing from a face video, no touch.
    SCGSeismocardiography: feeling the heartbeat as a tiny chest vibration with the accelerometer.
    RMSSD / HRVHeart-rate variability: how much the gap between beats changes. Needs 60 s of clean data.
    Kalman filterKeeps a best guess plus how unsure it is, and blends in each new noisy reading by the right amount.
    SigmoidS-shaped curve 1/(1+e^(−z)) that squashes any number into 0..1.
    Band-pass filterKeeps only the frequencies in a range (here, heartbeat speeds) and removes the rest.
    ViterbiDynamic programming that picks the best sequence of choices (smoothest heart-rate path, most likely road).
    HMMHidden Markov Model: the true state (which road) is hidden; we see noisy clues (GPS points).
    CUSUMCumulative sum: adds up small deviations so a slow drift is caught.
    Median / MADMiddle value, and the middle distance from it. Outlier-proof versions of mean and standard deviation.
    METMetabolic equivalent: 1 = sitting still, 3.5 ≈ walking, 6 ≈ stairs.
    Lux / CCTBrightness, and colour temperature of light in kelvin (higher = bluer).
    C/N0Satellite signal strength. Drops when a tree or building is in the way.
    Shadow modeA model runs and is shown, but its output is not used to decide.
    NPU / GPU / CPUPhone chips. NPU is built for neural networks; GPU for graphics and big models like Gemma.
    LiteRT / TFLiteGoogle's runtime for running AI models on phones.
    JNI / NDKWays to call C code (like the WBGT library) from Kotlin on Android.
    ProvenanceWhere a reading came from: REAL, REPLAY or SIMULATED.
